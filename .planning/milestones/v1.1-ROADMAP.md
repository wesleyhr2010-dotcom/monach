## Milestone Summary

**Key Decisions:**

- Reused visual patterns from existing catalog page for vitrina consistency
- Price displayed from `ProductVariant.price` (exception to maleta immutability for public vitrina)
- Dedicated tracking endpoint for vitrina events (rather than reusing generic `/api/track`)
- Middleware owns cookie generation for defense in depth
- Templates return `EmailContent` instead of `void` for preview and testing
- Hybrid freshness: `AnalyticsDiario` for historical + `AnalyticsAcesso` for today
- CSV exports only `slug` to prevent PII leakage

**Issues Resolved:**

- Vitrina public access without auth via RLS policies
- Email inconsistency — all 7 templates now use unified wrapper
- Supabase Auth templates out of branding sync — now automated via CI/CD
- Admin analytics limited to operational metrics — now includes vitrina engagement

**Issues Deferred:**

- Multi-tenant / multi-marca — system remains exclusive to Monarca
- Checkout próprio na vitrina — remains WhatsApp-only
- Real-time analytics push — deferred, uses polling

**Technical Debt:**

- Deploy: SUPABASE_MANAGEMENT_API_KEY needs to be generated and added as GitHub secret
- Deploy: Run sync manually once before auto-sync works
- Deploy: Verify templates in Supabase Dashboard after sync
