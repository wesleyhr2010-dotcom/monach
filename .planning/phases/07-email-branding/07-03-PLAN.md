<task type="auto">
  <name>Task 2: Create sync script for Supabase Management API</name>
  <files>scripts/sync-supabase-auth-templates.ts</files>
  <action>
    Create `scripts/sync-supabase-auth-templates.ts` as a standalone TypeScript/Node script (runnable via `tsx` or compiled).

    **Behavior:**
    1. Read environment variables:
       - `SUPABASE_MANAGEMENT_API_KEY` (required)
       - `SUPABASE_PROJECT_REF` (required — project reference ID from Supabase dashboard)
       - `NEXT_PUBLIC_SITE_URL` (optional — used to validate logo URL accessibility)
    2. Read HTML files from `scripts/supabase-auth-templates/reset-password.html` and `scripts/supabase-auth-templates/invite-user.html`
    3. Call Supabase Management API:
       ```
       POST https://api.supabase.com/v1/projects/{ref}/config/auth
       Headers:
         Authorization: Bearer {SUPABASE_MANAGEMENT_API_KEY}
         Content-Type: application/json
       Body:
         {
           "mailer_templates": {
             "confirmation": null,  // não alterar
             "recovery": { "subject": "Monarca — Restablece tu contraseña", "content": "<html...>" },
             "invite": { "subject": "Monarca — ¡Bienvenida! Crea tu contraseña", "content": "<html...>" }
           }
         }
       ```
       Note: The Management API may require `confirmation` to be present even if not changed. Fetch current config first, then merge.
    4. Error handling:
       - If env vars missing → print clear error with setup instructions
       - If API returns 4xx/5xx → print response body and exit with code 1
       - If API rate limited (429) → retry with exponential backoff (max 3 retries)
       - On success → print "✓ Templates synced successfully" with timestamps
    5. Dry-run mode:
       - Support `--dry-run` flag: print what WOULD be sent without calling API
       - Support `--check` flag: fetch current templates and diff against local files
    6. Idempotency: running the script twice produces the same result (safe to re-run)

    **Implementation details:**
    - Use native `fetch` (Node 18+). If project uses older Node, use `node-fetch` or undici.
    - Read files with `fs.readFileSync` and `path.join(__dirname, ...)`
    - Type the API payload for clarity
    - Add shebang `#!/usr/bin/env node` for CLI usage
    - Add JSDoc header explaining purpose and required env vars

    **Verify script works:**
    - `npx tsx scripts/sync-supabase-auth-templates.ts --dry-run` should print the templates without error
    - Missing env vars should produce helpful error message
  </action>

|----------|-------------|

| GitHub Actions → Supabase API | Secrets injected at runtime. Must not leak in logs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-07 | Information Disclosure | Management API key in logs | mitigate | Script must NOT print API key. GitHub Actions redacts secrets automatically. Verify with `grep -v` in workflow. |
| T-07-08 | Tampering | Template content modified in transit | accept | HTTPS to api.supabase.com. Certificate pinning not required for this threat model. |
| T-07-09 | Denial of Service | Management API rate limit | mitigate | Script implements retry with exponential backoff (3 retries). Document rate limits. |
| T-07-10 | Elevation of Privilege | Workflow runs on any push to main | mitigate | Workflow only syncs templates — no database access. Scope limited by Management API permissions. |
