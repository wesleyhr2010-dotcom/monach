<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public landing → Server Action | Untrusted user input for lead submission |
| Admin → Supabase Auth | Admin action creates auth users — high privilege |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Elevation of Privilege | aprovarLead | mitigate | requireAuth(["ADMIN"]) enforced; transaction ensures atomicity |
| T-02-05 | Denial of Service | Email sending | accept | Email failure is caught and logged; does not rollback successful approval |
| T-02-06 | Information Disclosure | Temporary password | mitigate | Password sent only via email; not logged or returned to client |
| T-02-07 | Race Condition | Concurrent approval | mitigate | Serializable transaction with WHERE status='pendente' ensures only one approval succeeds |
</threat_model>
