    1. Install Playwright as dev dependency: `@playwright/test` plus browsers.
       Use `npm install -D @playwright/test` then `npx playwright install chromium` (chromium is sufficient; avoid installing all browsers to save time/space).
    2. Create `playwright.config.ts` at project root with:
       - testDir: "tests/e2e"
       - fullyParallel: true (for speed)
       - workers: process.env.CI ? 1 : 3 (CI must be 1 to avoid DB collisions)
       - webServer: { command: "npm run dev", port: 3000, reuseExistingServer: !process.env.CI }
       - projects: one project for Chromium desktop (1280x720)
       - use: { baseURL: "http://localhost:3000", trace: "on-first-retry", screenshot: "only-on-failure" }
       - globalSetup: "tests/e2e/global-setup.ts" (file to create in next task)
       - globalTeardown: "tests/e2e/global-teardown.ts"
    3. Add scripts to package.json:
       - "test:e2e": "playwright test"
       - "test:e2e:ui": "playwright test --ui"
       - "test:e2e:headed": "playwright test --headed"
    4. Create `.env.test.example` with template values:
       - DATABASE_URL (pointing to test DB, e.g., local Supabase or separate schema)
       - NEXT_PUBLIC_SUPABASE_URL
       - NEXT_PUBLIC_SUPABASE_ANON_KEY
       - SUPABASE_SERVICE_ROLE_KEY (needed for admin operations in seed)

    5. Ensure playwright.config.ts imports dotenv from .env.test if present.

<task type="auto">
  <name>Task 2: Create Global Setup, Auth, and Seed Helpers</name>
  <files>
    tests/e2e/global-setup.ts
    tests/e2e/global-teardown.ts
    tests/e2e/helpers/auth.ts
    tests/e2e/helpers/seed.ts
    tests/e2e/helpers/test-data.ts
    tests/e2e/helpers/db.ts
  </files>
  <action>
    1. Create `tests/e2e/helpers/db.ts`: Prisma client instance for E2E.
       - Import { PrismaClient } from "@prisma/client"
       - Export `prisma` instance using DATABASE_URL from .env.test
       - Must NOT use the cached/extended prisma from src/lib/prisma.ts (avoid triggering encryption extensions or complex setup)
       - Use a simple new PrismaClient({ datasources: { db: { url: process.env.DATABASE_URL } } })

    2. Create `tests/e2e/helpers/test-data.ts`: Factories for test entities.
       - `createTestReseller(overrides?)` → returns object with email, password, nome, telefone, etc. Use unique values (timestamp + random) to avoid collisions.
       - `createTestProduct(overrides?)` → returns object with nome, descricao, categoria_id, etc.
       - `createTestVariant(overrides?)` → returns object with sku, preco, estoque, etc.
       - All factories must generate unique identifiers (e.g., `e2e-${Date.now()}-${random}@test.com`)

    3. Create `tests/e2e/helpers/seed.ts`: Database seeding and cleanup.
       - `seedUser(role: 'REVENDEDORA' | 'COLABORADORA' | 'ADMIN', overrides?)` → creates Supabase Auth user + Prisma profile. Use Supabase Admin API (service role key) to create auth user, then create Reseller/User profile in Prisma.
       - `seedProductAndVariant()` → creates a Product + ProductVariant with stock
       - `seedMaleta(resellerId, items: {variantId, quantity}[])` → creates a Maleta with MaletaItems
       - `seedScenario()` → orchestrates the complete scenario: one admin, one colaboradora, one reseller, 3 products with variants, one active maleta for the reseller with 2 items
       - `cleanupScenario()` → deletes all seeded data in reverse dependency order (vendas → maleta_items → maleta → products → reseller → auth user). Use Prisma deleteMany with unique prefixes or track created IDs in a global array.
       - Target: complete seed < 10 seconds. Achieve this by using Prisma createMany where possible and avoiding unnecessary awaits.

    4. Create `tests/e2e/helpers/auth.ts`: Authentication helpers.
       - `loginAsReseller(page, email, password)` → fills login form at /app/login, submits, waits for navigation to /app
       - `loginAsAdmin(page, email, password)` → fills login form at /admin/login, submits, waits for navigation to /admin
       - `loginAsColaboradora(page, email, password)` → same as admin route
       - `logout(page)` → clicks logout or navigates to logout endpoint
       - All login helpers must wait for network idle after navigation to ensure session is established

    5. Create `tests/e2e/global-setup.ts`:
       - Check required env vars (DATABASE_URL, SUPABASE_SERVICE_ROLE_KEY)
       - Optionally run `prisma migrate deploy` or verify DB is reachable
       - Return empty object (Playwright expects this)

    6. Create `tests/e2e/global-teardown.ts`:
       - Clean any leftover test data (safety net) using a known prefix pattern

    7. Update playwright.config.ts to reference globalSetup and globalTeardown.
  </action>
