## Key patterns from codebase

**Existing tracking endpoint:**
- `src/app/api/track/route.ts` — bot detection via `BOT_PATTERNS` array, `mnrc_vid` cookie read/create, fire-and-forget Prisma insert, 204 silent response, 1-year cookie

**Middleware pattern:**
- `src/lib/middleware-auth.ts` — `updateSession(request)` returns `NextResponse.next()`, sets JWT refresh cookies
- `src/middleware.ts` — calls `updateSession(request)`, matcher excludes static files

**Locked decisions:**
- **D-02:** Endpoint dedicated `/api/vitrina/track` with whitelist: `catalogo_revendedora`, `clique_whatsapp`
- **D-03:** `visitor_id` generated via middleware + client (defense in depth)

**Cookie config (from SPEC):**
- Name: `mnrc_vid`
- Duration: 30 days (`maxAge: 60 * 60 * 24 * 30`)
- `sameSite: 'lax'`
- `path: '/'`
- `secure: process.env.NODE_ENV === 'production'`
- Not HttpOnly (must be readable by client JS for tracking)
</context>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser → /api/vitrina/track | Untrusted payloads (event type, reseller_id) |
| Middleware → Browser | Cookie injection crosses trust boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-05 | Tampering | /api/vitrina/track | mitigate | Strict whitelist on `tipo_evento` — only `catalogo_revendedora` and `clique_whatsapp` accepted; all others return 400 |
| T-06-06 | Denial of Service | /api/vitrina/track | mitigate | Bot detection via `BOT_PATTERNS` prevents crawler analytics poisoning; fire-and-forget insert never blocks response |
| T-06-07 | Information Disclosure | Tracking payload | mitigate | No PII in payload; `visitor_id` is random UUID, not linked to real user |
| T-06-08 | Spoofing | middleware cookie | mitigate | Cookie is set by server middleware with `secure` flag in production; client cannot forge server-signed cookie |
</threat_model>
