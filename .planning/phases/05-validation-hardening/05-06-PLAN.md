  <read_first>
    - package.json (scripts and dependencies)

  </read_first>
  <action>
    1. Create `.github/workflows/ci.yml`:
       ```yaml
       name: CI

       on:
         push:
           branches: [main]
         pull_request:
           branches: [main]

       jobs:
         quality-gates:
           runs-on: ubuntu-latest
           
           steps:
             - name: Checkout
               uses: actions/checkout@v4
             
             - name: Setup Node.js
               uses: actions/setup-node@v4
               with:
                 node-version: '20'
                 cache: 'npm'
             
             - name: Install dependencies
               run: npm ci
             
             - name: Lint
               run: npm run lint
             
             - name: Type check
               run: npm run typecheck
             
             - name: Run tests
               run: npm test -- --run
               env:
                 DATABASE_URL: ${{ secrets.DATABASE_URL }}
                 SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
                 SUPABASE_SERVICE_ROLE_KEY: ${{ secrets.SUPABASE_SERVICE_ROLE_KEY }}
                 NEXT_PUBLIC_SUPABASE_ANON_KEY: ${{ secrets.NEXT_PUBLIC_SUPABASE_ANON_KEY }}
             
             - name: Build
               run: npm run build
               env:
                 DATABASE_URL: ${{ secrets.DATABASE_URL }}
                 SUPABASE_URL: ${{ secrets.SUPABASE_URL }}
                 SUPABASE_SERVICE_ROLE_KEY: ${{ secrets.SUPABASE_SERVICE_ROLE_KEY }}
                 NEXT_PUBLIC_SUPABASE_ANON_KEY: ${{ secrets.NEXT_PUBLIC_SUPABASE_ANON_KEY }}
       ```
       
    2. **Update `.env.example`** (create if missing):
       ```bash
       # Database
       DATABASE_URL="postgresql://..."
       
       # Supabase
       SUPABASE_URL="https://..."
       SUPABASE_SERVICE_ROLE_KEY="..."
       NEXT_PUBLIC_SUPABASE_ANON_KEY="..."
       
       # Other
       NEXT_PUBLIC_APP_URL="http://localhost:3000"
       BREVO_API_KEY="..."
       ONESIGNAL_APP_ID="..."
       R2_BUCKET_NAME="..."
       R2_ACCOUNT_ID="..."
       R2_ACCESS_KEY_ID="..."
       R2_SECRET_ACCESS_KEY="..."
       ```
       
    3. **Add CI badge to README** (if README.md exists):
       ```markdown
       ![CI](https://github.com/{owner}/{repo}/actions/workflows/ci.yml/badge.svg)
       ```
       
    4. **Document secrets setup:** Add a comment block at the top of `ci.yml`:
       ```yaml
       # Required GitHub Secrets:
       # - DATABASE_URL: Staging PostgreSQL connection string
       # - SUPABASE_URL: Supabase project URL
       # - SUPABASE_SERVICE_ROLE_KEY: Service role key for admin operations
       # - NEXT_PUBLIC_SUPABASE_ANON_KEY: Anonymous key for client-side auth
       #
       # Configure at: Settings → Secrets and variables → Actions
       ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions → Staging DB | CI has access to staging secrets; must not access production |
| PR → CI execution | Untrusted code runs in CI; sandboxing required |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-15 | Information Disclosure | Secrets in CI logs | mitigate | Use GitHub Secrets (masked in logs); never echo secrets; use `secrets.*` context only |
| T-05-16 | Elevation of Privilege | Malicious PR exfiltrates secrets | mitigate | CI runs on `pull_request` trigger (not `pull_request_target`) — no write access to secrets; use `permissions: read-all` |
| T-05-17 | Denial of Service | Resource exhaustion in CI | accept | Standard GitHub Actions limits apply; no custom runners |
</threat_model>
